# 卡通农场库存助手

面向《卡通农场》国际服的网页库存规划工具，用于记录货仓与粮仓库存、设置目标库存、展开生产链需求，并安排设备和基础原料的生产顺序。

## 功能

- 库存记录：维护当前数量、目标数量和隐藏状态。
- 缺货优先级：综合目标差额、下游需求和生产成本辅助排序。
- 生产计划：递归展开产品需求，并先扣除库存中可供下游使用的余量。
- 生产完成：增加成品库存，同时按配方扣除原料；原料不足时不会误记完成。
- 生产链查看：展示产品、原料、设备、生产时间和上下游用途。
- 设备动线：按当前生效配方把设备分成蛇形巡视段，尽量先安排原料和来源环节；可搜索设备或产品，并高亮直接上下游。
- 数据编辑：可修改名称、设备、原材料、生产时间和目标等字段。
- 数据校对：集中查看用户修改、缺失图片和核对状态，并为物品上传本地图片。
- 自定义排序：可拖动生产设备及设备内产品，并保留个人排列习惯。
- 数据保存：浏览器自动保存使用状态，内置服务将可持久化数据写入仅保留在本机的 `data.json`。

## 运行

```bash
npm install
npm start
```

然后打开：

```text
http://127.0.0.1:4173
```

也可以直接打开 `index.html` 预览页面。直接打开和 `http://127.0.0.1:4173` 使用不同的浏览器存储空间；长期使用和保存数据时，请统一通过 `npm start` 启动服务。

## 隐私与数据

- GitHub Pages 版本不需要账号，也不包含统计或广告脚本；库存、编辑、排序和核对状态保存在当前浏览器。
- 用户上传的物品图片保存在浏览器的 IndexedDB 图片库，不会自动上传到 GitHub 或其他网站。
- 通过 `npm start` 运行时，本地服务只把受支持的 `hd_*` 数据写入本机的 `data.json`，并用版本校验阻止旧页面静默覆盖新数据。
- 仓库中的 `public-data.json` 只包含公开展示所需的配方修正、核对状态和排序，不包含真实库存、仓库容量或界面偏好。
- 导出的 v4 备份可能包含用户上传图片。备份文件应按个人数据保管；导入前会先校验，失败时会同时回滚数据和图片。

## 校验

```bash
npm run test:data
npm run test:core
npm run test:server
npm run test:ui
```

第一次运行 UI 测试时，可能需要安装 Playwright 浏览器：

```bash
npx playwright install chromium
```

UI 和服务端测试使用系统临时目录中的独立 `data.json`，不会把测试字段写入项目根目录的用户数据。

## 数据状态

- 内置基础数据包含 465 个物品和 57 个生产分组；应用保存的修改后，当前实际生效 460 个物品。
- 物品、设备和配方以《卡通农场》国际服的简体中文译名维护。
- 部分水果、鱼肉、礼券等非设备生产物会以 `0s` 或基础资源形式存在。
- `wiki_products.json` 仅作为交叉校验参考，不会自动覆盖用户保存的数据。
- 游戏版本、活动内容和中文译名可能变化，关键数据仍建议结合游戏内信息复核；发现差异时可直接在网页中修改并保存。

## 目录

- `index.html`：主应用。
- `planner-core.js`：库存需求与配方关系的纯计算模块。
- `catalog-migration.js`：目录 ID、浏览器数据与旧备份的一次性兼容迁移。
- `catalog-id-image-mapping.json`：公开保留的人工确认审计记录，不参与网页日常运行。
- `public-data.json`：GitHub Pages 使用的公开基础数据，不含真实库存和仓库容量。
- `data.json`：本机运行时的库存与生产数据，已由 Git 忽略，不发布到 GitHub；首次运行时会从公开基础数据安全初始化。
- `icons/`：物品和设备图标。
- `vendor/`：静态发布所需的第三方浏览器运行时及其许可证。
- `server.js`：静态服务和保存接口。
- `validate.py`：数据一致性校验脚本。
- `wiki_products.json`：生产数据参考文件。
- `tests/`：核心算法、服务端和完整浏览器交互测试。
- `LICENSE`：项目代码的 MIT 许可证。
